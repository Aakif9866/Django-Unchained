# Learning backlog

Everything here was ⚡ built quickly to get SIDEQUEST working, and is worth studying properly. Items are ordered by
priority. "What I currently understand" is left for you to fill in honestly: it hasn't been assessed.

## SSRF and safe outbound HTTP (HIGH)

**Used in:** `apps/api_explorer/safe_http.py`, tests in `apps/api_explorer/tests.py`
**Why it matters:** any feature that fetches a URL for a user can be pointed at the server's own network or a cloud
metadata endpoint. This is one of the most common serious web vulnerabilities.
**What I currently understand:** not yet assessed.
**Need to learn:**
- Why checking the URL text isn't enough, and why every resolved IP must be checked
- DNS rebinding, and why the socket is pinned to the checked IP
- Why redirects must be revalidated at each hop
- IPv4-mapped IPv6, 6to4, Teredo and NAT64, and how they hide private addresses
- How the tests prove each defence against a real socket

## Server-authoritative rules and trusting the client (HIGH)

**Used in:** `apps/focusquest/services.py` (XP), `apps/typerush/forms.py` (WPM), `apps/snake/forms.py`,
`apps/maze_runner/forms.py`
**Why it matters:** anything the browser sends can be forged. Deciding what the server must own is a core design skill.
**What I currently understand:** not yet assessed.

**What I currently understand:** not yet assessed.
